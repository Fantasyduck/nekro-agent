# 持久任务和领域交接基础

本批实现持久来源任务、租约、有限重试、死信、单频道单任务在途，以及按频道的 legacy_guarded／shadow／service 模式和 writer_revision。默认仍为 legacy_guarded；没有自动启用后台任务，也没有自动接管线上来源。

服务模式以 scope 行锁协调模式变更和事实提交。旧工作器必须携带 writer_revision，提交时再次检查；超时租约和已被接替的 token 不能提交或确认。来源按原消息内容、发言人、频道和撤回状态复核；候选必须引用任务对应来源和真实原文片段。

事实批次、审计、outbox 和任务完成同事务；空结果也是合法完成。影子任务只存 shadow_result，既不发布事实，也不更新关系。至少一次投递和幂等槽配合，未声称跨数据库恰好一次。

DomainEventBroker 按消费者保存独立租约和确认，使用未投递集合逐批处理全部积压，不用最近 30 条或全局消息 ID 游标推断处理进度。关系消费者与索引消费者不能共用确认状态。当前 outbox 和消费者交接机制可调用，实际索引更新器、关系领域事件生成／订阅循环还未接入。

正式迁移 16 通过 `poe db-revision durable_memory_jobs` 生成并在临时 PostgreSQL 升级验证。来源时序冲突进入待复核；更早消息不能以迟到提交覆盖新事实。消息 ID 只在同频道、同来源时间的冲突裁决中作为稳定次序，不用作跳过未提交事务的消费水位。

灰度协调器在调用 set_mode 前仍需完成旧写入者停领、在途结束、历史增量对账和兼容投影追平。本方法只约束新管线，不能假装已经为所有旧 SQL 直写入口实现 fencing。自动消息 hook、补扫、模型抽取适配器、完整旧入口接管和线上切换属于后续接入工作。
