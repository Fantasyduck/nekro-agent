# M1：统一事实领域的增量实现

依据：2026-10-21 v1.1 详细设计。代码仅在隔离开发分支实现，未部署或导入线上记忆。

新增 MemoryService 和强类型请求契约；频道工作区映射必须由真实频道记录证明。事实单值版本替换、多值属性、人工确认保护、来源校验、幂等请求、删除全部历史版本、共享授权及撤权均经过统一门面。Scope 行锁串行化同频道发布；幂等槽防止迟到重试恢复旧值。JSONB 使用 `{value: ...}` 信封，保留字符串、数字、布尔、null 与复合值类型。

新增 11 张增量表；正式迁移 `15_20261021101733_unified_fact_service.py` 通过 `poe db-revision unified_fact_service` 生成，保留 MODELS_STATE。在独立 PostgreSQL 15 中从迁移 0 升级到 15，通过 39 项真实事务测试和 `poe lint`。

事实变更、审计、索引 outbox 和领域 outbox 同事务提交；事件仅含 ID 与 schema 版本，不复制事实正文。新增 mem_write_request 是为稳定命令去重设置的实现细化，不能由新 pipeline_version 绕过删除。被删除事实原证据的迟到重放被拒绝；用户可以通过新的有效来源重新明确保存。

本批不接管核心／天使旧抽取任务、不启动后台消费者、不改管理页面或 QQ 运行状态。M2 需要实现任务租约、重试、写入 fencing、按消费者交接和恢复；M3/M4 需要完成统一上下文、插件门面、旧数据迁移和灰度。向量／中文全文新索引、历史查询、候选审核和物理清理尚未实现。未来和早于当前版本的生效时间先进入 pending_review，不自动覆盖当前值。

关系、好感度与人格继续沿用天使现有实现。is_admin 和 RequestContext 只能由经过认证的服务端适配器注入，不能作为模型参数或新的未鉴权 HTTP 接口公开。
